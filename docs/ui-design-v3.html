01 · Design Context

先说清楚：这是为谁设计的

设计方案的质量取决于对使用情境的理解，而不是对代码的阅读。以下是本次设计的上下文假设—— 如果任何一条与实际不符，成本很低，改这一节就能重跑整套令牌。

谁

正在做体重管理的中文用户，20–40 岁

多数是第一次认真记录。他们不是健身教练，看不懂「TDEE」「热量缺口」这类词，需要界面替他们翻译。

何时

饭后、起床后、睡前的 10–30 秒碎片时间

单手、竖屏、常在移动中或光线不足的环境。这意味着：主操作必须在拇指区，关键数字必须一眼可读。

做什么

四件事，按频率排序

① 记录（体重/饮食/运动）② 判断「我还能吃多少」③ 看趋势获得正反馈 ④ 偶尔调整目标。

语气：可信，且不制造焦虑

这是减重类产品最容易做错的一点。超标就用刺眼的红色横幅警告，短期提高点击，长期让人卸载。 v3 的处理是：超标不再是「错误」，而是「信息」——配色从警告红换成中性琥珀， 并附一句接下来能做什么，而不是只说「你超了」。具体见 §5 今日热量卡。

与 v1 / v2 的关系

v1 清爽风

中性灰 + 强调绿，功能完整但缺乏记忆点，卡片同质化严重。

v2 活力青绿（当前线上）

加入沉浸式绿色渐变头部，视觉辨识度提升明显。但带来两个问题：渐变上的白字对比度不达标；渐变面积过大挤压了内容密度。

v3 静水（本方案）

收回装饰性渐变，把节省的视觉预算全部给数据和留白。品牌绿保留，但只用在「可行动」的地方。

02 · Audit

现状审计：实测出来的六个问题

对现有 App.vue 中的令牌逐项跑了 WCAG 2.1 相对亮度公式。 结果不是「感觉偏淡」，而是有明确数值的低对比——这些颜色正被用在正文、副标题和页脚上。

三个结构性问题

1

两套令牌并行

App.vue 用 CSS 变量（品牌绿 #0E9E68），uni.scss 用 SCSS 变量（#10B981）。两套颜色不一致，改一处漏一处。

2

没有组件层

.card / .card-head / .btn / .field 在 6 个页面里各写一遍，散落着 #fff、#e6efea、#edf3ef 等硬编码色值。

3

圆角与阴影不成体系

圆角出现 32/24/18/8/6/3rpx 六种值，阴影两种。层次主要靠阴影而非描边，在浅底上区分度不足。

03 · Principles

五条设计原则

01

数字是主角，其余都是陪衬

用户打开这个应用只想看两个数：体重多少、还能吃多少。所有排版权重向这两个数字倾斜，装饰元素让位。数字统一启用等宽数字（tabular-nums），避免刷新时跳动。

02

颜色只表达意义，不做装饰

绿色＝可行动/达标，琥珀＝需要注意，红＝超标，蓝＝消耗。任何一个色块都要能回答「它想让我做什么」，否则改成中性色。

03

先描边，后阴影

浅色界面里，1px 描边比模糊阴影更能界定边界，也更省渲染。阴影只用于真正浮起的层（悬浮按钮、tabbar），且透明度压到 10% 以内。

04

拇指优先，主操作在下

高频操作落在屏幕下半部；危险操作（删除）永远不与主操作并排，且放在远端或二级入口。

05

不惩罚用户

漏记、超标、断卡都不是错误。空状态和超标态给出的是下一步建议，不是警告。

+

一个记忆点：液态热量环

热量环不使用常规甜甜圈的均匀粗细，而是用带圆头的粗描边 + 呼吸式的渐变填充，让「剩余额度」看起来像容器里的水位——这是本方案唯一的装饰性表达。

05 · Components

组件库

下面这些都是真渲染出来的组件，不是图片。切换右上角的深色模式可以直接看另一套令牌下的效果。

按钮

三种层级：主按钮（每屏最多一个）、次级（浅底同色）、幽灵（取消/次要）。 最小高度 44px（小程序 88rpx）满足触摸目标要求；按压反馈用 transform:scale(.97) 而非改背景色，成本更低。

表单

标签永远可见（不用占位符代替标签）。选填项在标签里直接标「选填」，降低填写压力。 聚焦态用 3px 品牌色外环，不用 outline——小程序的 outline 表现不一致。

06 · Layout

布局系统

配色解决的是「看不看得清」，布局解决的是「找不找得到」。这一节处理三件事： 把关键数据拉进首屏、把零散的间距收进 4pt 网格、给每张图表补上能真正读数的参照。

首屏预算：575px

按最窄的主流机型 iPhone SE（375×667）算：减去状态栏 44px 和 tabbar 约 48px， 真正可见的高度只有 575px。用它当预算线，而不是按 iPhone 15 的 800px 来设计—— 否则小屏用户永远看不到重点。下面两张图按 1:4 缩放，虚线是首屏线。

六条布局规则

01

首屏预算 575px

按最窄主流机型倒推，不是按最大机型。最高频的两个数据块必须完整落进这条线内。

02

一屏一个视觉重心

记录页的重心是体重输入框（56px 高、24px 字），其余字段一律常规尺寸。处处强调等于没有强调。

03

等分用 grid，不用 space-between

凡是「N 等分」的横向排列（7 天打卡、三宫格指标）一律 repeat(N,1fr)。space-between 会让首尾贴边。

04

手感与视觉解耦

紧凑控件（30px 药丸、32px 删除块）用 ::after{inset:-7px} 把热区补到 44px。看着精致，按着舒服。

05

每张图都有数值参照

没有刻度的柱状图只能比较高低、读不出大小。y 轴刻度 + 一条预算基线，成本极低，信息量翻倍。

06

长文本省略，数字等宽

所有可能变长的文本加 ellipsis；所有数字加 tabular-nums，避免刷新时数字跳动。

07 · Screens

六屏高保真设计

375 × 812（iPhone X 基准），布局按 375 × 667 的首屏预算验证。所有元素使用上文的令牌与空间尺度，切到深色模式可整体验证。

08 · Dark Theme

深色模式 · 夜航

睡前称体重、躺床上补记饮食是很常见的使用场景，纯白界面在暗光下刺眼。深色模式不是把颜色反转， 而是重新配平：品牌绿提亮到 #4ECB8B 保证在深底上的可读性，阴影替换为更深的表面色。

表面抬升，不用阴影

浅色模式靠阴影表达层级，在深色模式下几乎不可见。改用三级表面色 #0E1512 → #16211C → #1D2A24 表达深度。

品牌色反转

深色底上需要更亮的绿。#4ECB8B 在 #0E1512 上对比度 9.02:1，作按钮填充时配深色文字同样 9.02:1。

饱和度下调

深色底会放大高饱和色的视觉冲击。语义色在深色下统一降低饱和度并提高亮度，避免夜间阅读疲劳。

令牌深色值用途对比度（on 页面底）结论
--ink-1#E8EFEA标题、主数字15.83 : 1AAA
--ink-2#A9BDB2正文9.35 : 1AAA
--ink-3#87998F说明、单位6.15 : 1AA
--brand#4ECB8B主色 / 按钮9.02 : 1AAA

实现方式：给根节点挂 data-theme="dark"，令牌全部用 CSS 变量，无需写两套样式表。 小程序端可读取 uni.getSystemInfoSync().theme 跟随系统。

09 · Accessibility

无障碍与可用性清单

已经内置在设计里的

· 全部文字/背景组合 ≥ 4.5:1（正文）、≥ 3:1（图形与描边），实测数据见 §3
· 所有可点击元素最小 44 × 44px
· 颜色从不作为唯一信息载体：状态都同时有图标、文案或形状变化（如打卡格同时改变底色与显示对勾）
· 表单标签常驻可见，不依赖 placeholder
· 支持系统「减弱动态效果」偏好，开启后关闭全部过渡

开发时需要补上的

· 所有 <image> 补 aria-label；装饰性图片标 aria-hidden
· tabbar 四项加 aria-role="tab" 与选中态 aria-selected
· 自定义控件（分段控件、开关）补 aria-checked / aria-pressed
· 体重输入框 type="digit" + inputmode="decimal"，唤起数字键盘
· 错误提示同时用图标 + 文案 + 颜色三重表达
